# RepoCity: 5-minute live demo script

**Setup (before the audience arrives, about 3 minutes)**

1. Start the app: `docker compose up` (or the native commands in the README), and open **http://localhost:5173**
   in Chrome or Edge, window at least 1280 px wide (F11 for full screen looks best).
2. Click the **pallets/flask** demo card once to warm the cache, then click the **RepoCity** logo to return home.
3. Have a second tab ready on `reports/report_draft.md` (E1 table) as a backup visual.
4. Turn off notifications. The demo needs **no internet**.

---

## 0:00–0:30 · The hook (home page)

> "Every repository is a city. Each building is a source file, each district a directory. The question
> I asked is: *from a project's own history, can we predict which files will need bug fixes in the next six
> months, and does that beat what practitioners use today?*"

* Point at the three demo cards: Python, JavaScript, Java. "These are pre-analysed, so the demo runs offline."

## 0:30–1:30 · Reading the city

* **Click** the **pallets/flask** card. The city loads in about a second.
* "Footprint is lines of code, height is churn (how much a file changed), colour is predicted bug risk: green is low, red is high."
* **Drag** to orbit once; **scroll** to zoom into the `src/flask` district. The labels fade in as you zoom.
* **Hover** the tallest red building: the tooltip shows path, LOC, churn and risk.
* **Click** it: the file panel opens.
  * "Here is *why* the model thinks it is risky: SHAP contributions. Red bars push the risk up."
  * Point at the sparkline (commits per month), the authors (initials and pseudonymous ids only; e-mails are hashed),
    and the list of bug-fix commits.
* Close the panel (✕).

## 1:30–2:30 · Time travel

* **Drag the timeline slider** all the way left (2010), then press **Play** (or **Space**) at **8×**.
* While it plays: "Each step is one month. Watch `src/flask` form; red sparks are commits that SZZ later
  traced as the *birth* of a bug. The layout is computed once from every file that ever existed, so buildings
  never jump while history replays."
* Press **Space** to pause around 2017–2018, then drag the slider back to the end.

## 2:30–4:15 · The signature moment: Prediction vs Reality

* **Click** **Prediction vs Reality** (top right).
* "I freeze the city at a cutoff. The model was trained *only* on data before this date (windows ending 6, 12
  and 18 months earlier), so it cannot have seen the answer. The amber outlines are its top-20 riskiest files."
* Leave the cutoff on the latest **evaluation cutoff**. **Click** **Reveal reality**.
  * Diamonds drop onto every file that really received a bug fix in the next 6 months. **Green** = the model
    flagged it, **magenta** = missed.
* Read the score card aloud: *hits@20*, precision, and **Recall@20%LOC**. "If a reviewer can only read 20% of
  the code, how many of the future bug fixes do they cover?" Compare with the **Hotspot** column, the
  CodeScene-style baseline.
* Switch **k** to 10 to show the numbers update. "These are exactly the numbers in my evaluation tables. The
  end-to-end test checks the UI against the backend."
* Optional: pick an older cutoff in the dropdown and reveal again. "This is one of six rolling cutoffs per project."

## 4:15–5:00 · Results and honesty (one slide or the report tab)

* Show the E1 summary table / Figure `e1_metrics_bars.png`, then state the headline from the report
  (`reports/report_draft.md`, "Conclusion"), **including where the model did not win**.
* "Everything is regenerated by one command, `python experiments/run_all.py`, across 12 pinned repositories in 3
  languages, with Wilcoxon tests and effect sizes."
* Close: "RepoCity makes defect prediction *inspectable*. You can see the history, see the prediction, and see
  reality."

## Fallback plan

| Problem | What to do |
|---|---|
| Docker won't start | Run natively: `python -m repocity.cli serve` + `cd frontend && npm run dev` (README, Option B). |
| Browser shows "backend not reachable" | Backend not running: start it, then refresh. The demo cards appear once `/api/demo` answers. |
| City is slow (weak GPU, projector laptop) | Quality drops automatically (a "reduced quality" note appears). Or add `?quality=low` to the URL before `#`, e.g. `http://localhost:5173/?quality=low#/city/...`. Use the Flask city (fewest buildings). |
| A click doesn't open the panel | Use **Find a file** (type `app.py`, Enter): the camera flies there and the panel opens. |
| Playback stutters at the start | History is still prefetching (see "loading history %" under the speed buttons). Wait a few seconds or use a lower speed. |
| WebGL unavailable / blank canvas | Show the screenshots in `docs/screenshots/` (01–12 follow the demo order) and the report figures. |
| Live "paste a URL" requested | Use a small repo, e.g. `https://github.com/pallets/click` (about a minute). If there is no internet, explain that the pipeline is identical to the demo cities and show the progress screenshot. |
